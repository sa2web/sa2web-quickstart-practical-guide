# Sa2web 快速入门与实战指南

《Sa2web 快速入门与实战指南》是一本面向企业管理员、IT 运维、信息安全团队、业务系统负责人和 AI 自动化实践者的 Sa2web 中文实战书。它不是单纯的安装笔记，而是围绕“企业如何安全、可控、可审计地访问 Web 系统”这一核心问题，系统讲解 Sa2web 的部署、配置、授权、协作、安全策略、审计回放、站点定制和 MCP / AI Agent 浏览器访问。

如果你正在寻找 Sa2web 教程、Sa2web 快速入门、企业远程浏览器方案、云浏览器访问控制、SaaS 账号共享治理、内部站点安全访问、浏览器堡垒、远程浏览器审计或 AI Agent 受控浏览器访问，本书可以作为从零落地到团队使用的实践路径。

## Sa2web 解决什么问题

在传统企业 Web 访问模式中，员工通常直接用本地浏览器访问 SaaS、业务后台、供应商系统或内部站点。这样会带来一组长期存在但容易被忽视的问题：

- 账号、Cookie、Session 和浏览器环境分散在员工设备上；
- 管理员很难统一控制谁能访问什么系统、使用哪个账号访问；
- SaaS 账号、内部系统 URL、业务参数和敏感页面容易暴露；
- 员工复制、下载、截图、传播敏感数据的行为难以集中约束；
- 外包、客户、临时人员、供应商和跨团队协作需要开放访问，但又不能直接交付账号密码；
- 员工离职、岗位变动或项目结束后，账号会话和访问痕迹难以完整回收；
- 出现问题后，管理员缺少可回放、可追溯的浏览器操作证据；
- AI Agent 需要访问业务页面时，缺少权限边界清晰的受控浏览器环境。

Sa2web 要解决的，就是把“个人设备打开网页”变成“企业集中治理的浏览器访问流程”。它让访问入口、账号会话、浏览器运行环境、权限策略、数据保护和操作审计从终端设备中抽离出来，进入统一的远程浏览器工作空间。

## Sa2web 是如何做到的

Sa2web 的核心思路是：用户仍然通过自己的浏览器打开页面，但真正访问目标站点的是部署在受控服务器环境中的远程浏览器。

通过这种架构，企业可以把 Web 访问拆成几个可管理对象：

- **机器与浏览器实例**：在 Linux x86_64 服务器上运行远程浏览器环境，承载实际访问行为；
- **云浏览器**：为用户提供独立、受控的远程浏览器配置文件，减少本地设备差异和数据散落；
- **SaaS 站点**：把外部业务系统配置为统一入口，管理员可以预登录账号后授权员工使用，而不直接交付账号密码；
- **工作空间**：固定站点账号、浏览器环境和访问配置，适合多账号、多店铺、多客户、多地区等业务场景；
- **内部站点**：让员工通过统一入口访问内网系统，终端设备不必直接暴露在内部网络中；
- **协作链接**：为客户、外包、临时人员或交付场景创建可控、可过期、可加密码的访问链接；
- **用户、角色、分组和权限**：用统一授权模型管理用户、站点、工作空间、内部站点、代理和功能权限；
- **目标地址保护、水印和敏感内容控制**：减少真实 URL、内部路径、业务参数和敏感字段暴露；
- **录制与回放**：记录关键浏览器访问过程，用于审计、排查、培训和责任追溯；
- **站点脚本与接口脚本**：对复杂页面做增强、遮蔽、自动化辅助或系统集成；
- **MCP / AI 访问**：让 Codex、Claude Code、Cursor 等 AI 客户端在企业授权范围内操作远程浏览器。

这些能力组合起来，使 Sa2web 更像一个面向浏览器访问的企业控制平面：它既能服务普通员工访问，也能服务临时协作、敏感系统治理和 AI Agent 自动化。

## 本书会带你完成什么

读完本书后，你应该能够从零部署一套可用的 Sa2web 环境，并完成一条企业内部常见的访问治理闭环：

- 安装 Sa2web，并完成许可证、机器、浏览器和证书配置；
- 创建云浏览器、SaaS 站点、内部站点和工作空间；
- 用工作空间管理多个业务账号和固定浏览器环境；
- 用协作链接向外部人员开放有限访问；
- 通过用户、管理员、角色、分组和权限建立授权模型；
- 对敏感站点启用 URL 保护、水印、复制下载限制和敏感内容控制；
- 对关键业务访问启用录制回放；
- 为复杂站点编写脚本，做页面增强、数据遮蔽或自动化辅助；
- 配置 Sa2web MCP，让 AI Agent 在受控账号和授权边界内访问业务页面；
- 排查部署、访问、证书、权限、MCP 和 Passkey 常见问题。
